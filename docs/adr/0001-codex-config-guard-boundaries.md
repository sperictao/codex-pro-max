# Codex 配置看守的生命周期与回滚边界

Codex 配置看守（见 CONTEXT.md）的轮询**只在 launcher 运行期间生效**——launcher 关闭即停止看守，不安装 launchd/系统服务。同时，解锁参数或全局关闭功能时**一律不回滚**已写入 codex 文件的值，值留在原地，只停止看守。

两个决定是同一权衡的两面：这个功能的定位是"launcher 顺手提供的看守"，不是常驻配置管理 agent。做常驻服务意味着装系统服务、处理权限与自启动失败，工程量高一个量级；做回滚则要在配置文件被多方（codex 自身、其他工具）持续改写的前提下维护"启用前原值"，语义是伪精确。两者都用备份兜底替代：任何写入前目标文件已备份到 `~/.codex/dashi-backups/`，想撤销手动恢复即可。

**Consequences**：用户若期待"锁了就永远锁"，launcher 关闭期间的漂移不会被纠正（下次启动后的首个轮询周期会改回）；若期待"关闭功能=恢复原状"，需要手动从备份恢复。
