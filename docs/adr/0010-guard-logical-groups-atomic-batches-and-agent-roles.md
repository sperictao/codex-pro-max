# Guard 采用跨文件参数组、原子批量操作和多子代理角色

配置看守把“参数组”与“看守文件”拆成正交概念：参数组围绕配置目的组织参数并可跨文件，每个参数只能属于一个组；看守文件继续作为格式校验、备份和写入边界。全部或组级启用、锁定、解锁、禁用采用全有全无的批量操作，先校验整个作用域、每文件只写一次，失败时恢复本批次快照，避免跨文件配置只成功一半；所有 Guard 写操作共用单一事务入口，批量期间暂停轮询并拒绝并发写入。

多个子代理配置建模为可同时存在的“子代理角色集合”，而不是同一 `default` 角色下只能激活一个的配置档。角色通过结构化字段管理并显式声明模型与推理强度；磁盘已有角色只发现、不自动接管，原始 TOML 不成为第二条编辑路径。`default` 是不可重命名、不可删除的受保护角色；停止管理只放弃 Guard 所有权，删除角色才在备份后移除实际文件。这些边界避免隐式切换、静默覆盖外部文件和多份当前配置状态。

角色 ID 同时作为 Codex `agent_type` 和 `agents/<id>.toml` 文件名主体，使用 `[a-z][a-z0-9-]{0,62}`、大小写不敏感唯一且创建后不可变；显示名称单独管理。创建角色时只允许从当前 Codex 模型目录选择支持 V2 多代理的模型，推理强度按模型能力过滤，不允许自由输入模型名。已托管角色后来失去能力支持时保留配置并标记 Unsupported，但阻塞其作用域及全局的启用、锁定。最多托管 32 个角色，所有未托管角色仍可见。

Guard 在 AGENTS.md 托管区块中生成角色目录，主代理按角色用途选择 `agent_type`，派生时固定 `fork_turns = "none"`，不通过单次调用覆盖角色文件中的模型或推理强度；运行时审计再按 `agent_type` 对照期望配置。界面将生命周期状态（Disabled、Applied、Locked、Mixed）与健康状态（Healthy、Drifted、Invalid、Unsupported、Error）分开呈现，避免把“已锁定”误解为“配置有效”。角色采用纵向可折叠卡片，默认角色固定首位，其他托管角色可排序，未托管角色单列发现区。

旧版整文件托管只在期望内容与实际文件均有效且一致时自动迁移为结构化 `default` 角色；冲突或无效内容必须经迁移向导选择采用实际文件、采用已存期望值或安全默认值，选择前不得写盘。迁移完成后移除旧整文件所有者，禁止双重锁定；其他 `agents/*.toml` 只进入发现区。内置参数显式归组，无组的旧自定义参数进入不可删除的内置“未分类”组。

每个看守文件显式声明 `toml`、`json`、`markdown` 或 `plain_text` 格式，运行时不靠扩展名猜测。格式、参数语义、Codex 能力和写后复查组成同一条分层校验管线；诊断携带稳定错误码和文件、字段、行列位置，不自动修复或静默降级。文件路径和参数路径规范化后执行唯一所有权检查：托管角色独占对应角色文件，AGENTS.md 只按标记区块拥有角色目录，外部集成已拥有的键不能再交给 Guard。

批量命令暴露预检、备份、写入、写后复查、恢复和完成报告阶段，并在写入前建立事务日志。预检失败零写入，写入或复查失败恢复全批次；恢复失败升级为 Critical Error，暂停相关轮询并保留快照，直到显式恢复。Codex 模型目录离线时，最近一次能力快照只支持展示和页面内存草稿，不得持久保存角色期望；保存角色、启用、锁定仍要求实时刷新，解锁、禁用不受此限制。

新建角色不隐式继承默认角色；复制角色也不复制生命周期、健康状态和审计历史。内置参数组顺序固定，自定义组可排序，“未分类”为空时隐藏。全局和组级动作统一采用启用、锁定、解锁、禁用的顺序和无播放三角形的图标。操作审计仅保留本地最小元数据，按 30 天或 500 条清理，不记录提示、指令、文件原文、密钥或完整用户路径。

事务日志在首次写入前持久化快照、原内容哈希和恢复阶段；每次落盘前重新核对哈希，外部抢写即中止并恢复。应用启动时必须先处理未完成事务，恢复证据不完整时不猜测文件状态，而是进入 Critical Error 并关闭相关文件的轮询和写入。停止管理和删除角色也走同一原子事务入口：前者保留文件并回到发现区，后者备份后删除文件；两者都同步移除角色目录和 Guard 状态，`default` 禁止执行。

角色文本采用明确长度和编码边界，AGENTS.md 角色目录只写入转义后的单行摘要，不复制角色指令。未知 TOML 字段与注释在语法有效时保留为 Warning，只有 Codex 正式诊断明确拒绝时才阻止接管。Guard schema 升级前备份旧配置；迁移未决只暂停 Guard，不影响启动器其他功能，禁止静默重置，降级须先恢复旧备份。

本决策的验收不仅包含常规单元测试，还必须覆盖格式夹具、所有权冲突、事务阶段故障注入、崩溃恢复、并发拒绝、迁移、能力离线、角色上限、双状态聚合和无障碍交互，并在隔离 Codex 目录中完成真实桌面冒烟。本期不扩展到原始 TOML 编辑、云端下发、第三方 provider、Codex 安装升级或子代理自动执行与跑分。
