# v1.21.3

## Changes

- **Vendored taskboard updated to upstream v1.1.23-beta.2** (the 41 commits
  since the previous v1.1.22-beta.4-era merge, spanning v1.1.22-beta.5/beta.6,
  v1.1.22, and v1.1.23-beta.1/beta.2), while preserving the launcher runtime
  endpoint discovery (`~/.codex-pro-max/launcher-runtime.json`) and the
  injector reliability fixes. Highlights:

  - **Unified AI message permissions**: a new `shared/codex-permissions.mjs`
    replaces per-call permission mapping; `server/app.mjs` and the AI
    composer consume a single source of truth.
  - **Remote automation rework**: `turn/completed` waiters are keyed by exact
    turn id instead of polling `thread/read`, and candidate tasks are claimed
    one-by-one rather than the first eligible one blocking the queue.
  - **Release/updater metadata refactor**: new `scripts/release-metadata.mjs`
    and `release-metadata-cli.mjs` shared across macOS/Linux verification;
    the updater moves to plugin download + signature verification.
  - **Task input/relation split**: `shared/task-input.mjs` and
    `shared/task-relations.mjs`; `taskctl` request/error handling is
    consolidated.
  - **Frontend split**: `documentModel.ts`, `useTaskCardDragPreview.ts`;
    `styles.css` trimmed; AI composer draft ownership and parsing fixed.
  - **Server**: `database.mjs` / `ai-chat.mjs` / `jira-integration.mjs` /
    `codex-app-server.mjs` batched and serialized where order matters.
  - **CI speedups and new Windows-side test coverage** (upstream infra, no
    packaged behavior change).

- **Launcher-side merge conflict resolved in the fork**: the only conflict
  was in `scripts/codex-injector.mjs`'s initial-injection retry; the fork's
  two-round retry loop was kept and now emits upstream's new
  `waitingForCodex` launcher event only after the retries are exhausted.
  Other fork adaptations (Windows page recognition, `taskctl` default
  runtime-file discovery, sidebar data-hook fallback) were in blocks upstream
  did not touch and carried over unchanged.
