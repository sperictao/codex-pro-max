# v0.2.5

修复独立窗口模式与完整模式注入失败 `No Codex renderer target found`（启动后立即退出）的问题，注入器等待逻辑带监控日志并支持重试。

## Bug Fixes

- 修复注入失败 `No Codex renderer target found`：CDP 调试端口比 Codex 渲染窗口早数秒就绪，注入器一检测到端口就立即查找注入目标导致落空退出；新版 ChatGPT.app（Chrome 151）窗口创建变慢暴露该竞态。现在注入前轮询等待渲染目标出现（最长 15 秒）
- 修复 Codex 窗口白屏 `Something went wrong`：页面初次加载未完成时执行 reload 会让 `app://` 协议加载失败（ERR_FAILED）。现在 reload 前等待 `document.readyState === "complete"`（最长 20 秒）
- 修复 `Page.reload` 发送失败时未处理的 rejection 导致注入器进程以裸栈崩溃

## Improvements

- 注入重试：单个窗口注入失败重试 3 次（间隔 2 秒），首次注入整体失败再重试一轮，watch 模式持续兜底不变
- 注入器监控日志：等待开始/完成（带耗时）、每次重试均输出带时间戳的日志，启动器界面可直接看到注入进度与失败原因
- 启动器采集注入器/服务子进程 stdout/stderr 尾部日志，启动后立即退出（秒退）时把退出码与日志尾部抛给 UI，不再让"运行中"掩盖失败
- 注入器启动统一走跨平台的 `--watch`：由启动器负责拉起带 CDP 端口的 Codex 实例，支持独立窗口模式（macOS `open -n` 不动现有窗口）与完整模式；注入器获得 taskboard 端口配置，非默认端口下也能正常监督服务
