# v1.3.3

修复版：停止 dsh 远程访问时回环反代被开机自启重新拉活；打包应用内安装 manage-taskboard 技能报「Skill 源路径不存在」，并为发布前置校验补上打包资源存在性检查。

## Fixes

- **停止远程访问后回环反代关不掉**：开启开机自启时，`dsh_stop` 用 pkill 杀进程，launchd `KeepAlive`（macOS）/ systemd `Restart=on-failure`（Linux）会把被杀的进程判作非成功退出立刻拉活——实测 pkill 后 2 秒反代就用新 PID 重新监听 3898，Stop 形同虚设。现在停止前先卸载自启监管（`launchctl unload` 不带 `-w` / `systemctl --user stop`），只停本次、不改开机自启设置，plist/unit 保留下次登录仍自启；`kill_by_pattern` 保留为游离进程兜底。Windows 无 KeepAlive 不受影响

- **安装技能失败「Skill 源路径不存在」**：`install_skill` 从应用 resource 目录下的内置 taskboard 链接 `skills/manage-taskboard`，但 `tauri.conf.json` 的 bundle resources 清单漏了 `skills` 目录，打包后的 App 里该路径根本不存在，安装时源路径检查直接报错（开发模式走工作区 git 子模块所以从未暴露）。resources 清单补上 `"../vendor/dashi-taskboard/skills": "vendor/dashi-taskboard/skills"`

## Changes

- **`check:release` 新增打包资源存在性校验**：`scripts/check-release.mjs` 现在会逐一检查 `tauri.conf.json` bundle.resources 中被 git 跟踪的源路径真实存在（相对 tauri.conf.json 所在目录解析），本地打 tag 前与 CI validate job 都会秒级拦下「清单声明了但磁盘上没有」的资源缺失，防止此类打包漏资源问题回归。`dist/web` 等 gitignore 的构建产物不做存在性校验（CI validate 在构建矩阵之前运行，产物尚不存在）
- **AGENTS.md 发布须知补充**：新增 vendored taskboard 目录进打包时必须同步 bundle.resources 清单
