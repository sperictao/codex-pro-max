# v1.22.1

## Changes

- **Dialog close semantics are now explicit** — the shared `Modal` wrapper uses
  `onRequestClose` for Escape/outside-close requests instead of the misleading
  `onOverlayClick` name. Editable dialogs keep their normal dismissal behavior,
  while confirmation-only dialogs remain closed only by their explicit actions.
- **Navigation now has one deterministic global API** — `goto(view, section?)`
  is idempotent everywhere, including the command palette. The Settings and
  Integrations "click again to return Home" behavior is kept locally in the
  header instead of being hidden inside global store semantics.
- **Command palette accessibility metadata fixed** — its hidden dialog title and
  description now live inside the actual portalled `DialogContent`, keeping the
  accessible dialog relationship and DOM lifecycle aligned.
- **Craft conformance gate tightened** — `check-craft` v2 checks explicit state
  contracts for each key interactive primitive, validates the complete
  sidebar/chart theme bridge, and rejects UI primitives with no production call
  site. The documentation now describes the gate's real static guarantees rather
  than treating it as a substitute for interaction testing.
- **Unused primitives removed** — `ButtonGroup` and `Separator` were deleted
  until a real call site requires them, matching the project's on-demand
  primitive policy.

## Upgrade notes

- No migration is required; persisted launcher configuration and localStorage
  keys are unchanged.
- Header navigation keeps the existing second-click behavior for Settings and
  Integrations, while programmatic navigation is now deterministic.
- Editable dialogs can still close with Escape or outside interaction; explicit
  confirmation dialogs remain button-only.
