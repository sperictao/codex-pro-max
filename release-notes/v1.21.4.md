# v1.21.4

## Fixes

- **Install Skill: dangling-symlink no longer fails with
  "File exists (os error 17)".** When `~/.codex/skills/manage-taskboard`
  holds a symlink whose target has since been deleted (for example, a link
  written by an older app install that was later removed), the install flow
  checked for an existing link with `Path::exists()` — which *follows* the
  link and therefore returns `false` for a dangling one. The stale link was
  never removed, and the subsequent `symlink()` call failed with `EEXIST`.
  The presence check now uses `symlink_metadata()` (does not follow links),
  so a dangling link is recognized and removed before the new one is
  created.

## Verification

- `cargo test --bin codex-pro-max` — 52 passed / 0 failed (new
  `skill_tests::install_skill_removes_dangling_symlink` reproduces the
  dangling-link EEXIST case; `install_skill_cleanup_is_noop_when_absent`
  covers the idempotent absent-path case).
- `node scripts/check-release.mjs --tag v1.21.4` passes.

## Note

- This fix prevents the failure going forward. If your machine already has a
  stale `~/.codex/skills/manage-taskboard` symlink written by an older build,
  remove it once by hand (`rm ~/.codex/skills/manage-taskboard`) so the
  install succeeds immediately.
