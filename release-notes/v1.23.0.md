# v1.23.0

## Changes

- **The model screen now covers Codex's whole provider schema instead of four
  fields** — a provider row used to expose `name`, `base_url` and one of two
  auth keys. It now manages every documented `[model_providers.<id>]` setting:
  `wire_api` (`chat` / `responses`), `query_params`, static `http_headers`,
  `env_http_headers`, `request_max_retries`, `stream_max_retries`,
  `stream_idle_timeout_ms`, `startup_timeout_ms`, `tool_timeout_sec`,
  `requires_openai_auth` and `supports_websockets`. The full field set lives
  behind the row's **Edit** button, so the main screen stays a summary.
  - **Keys this app does not know are kept, not dropped.** Codex adds provider
    keys faster than its reference table documents them (`requires_openai_auth`
    and `supports_websockets` are both in real configs already). Anything
    outside the managed set round-trips untouched and is listed read-only in the
    editor as “Keys kept as-is”.
  - Comments and hand-written subtables survive an edit: values are rewritten
    in place, so a note above `name = …` is not collateral damage.
  - Emptying a field removes the key rather than leaving `base_url = ""`.
- **Reasoning levels widened to match real configs** — the picker offered
  `minimal | low | medium | high`; real configs also use `max` and `none`, and
  the old list rejected them. The list is now
  `none | minimal | low | medium | high | xhigh | max`, sourced from one place
  in Rust.
- **Model catalog (models.dev) with a picker** — the model id field gains a
  search button that browses the catalog and shows each model's context window,
  max output and whether it supports reasoning. The active model row shows the
  same metadata for the current selection, and flags an id the catalog lists as
  unknown for the chosen provider. The catalog is a cache
  (`~/.codex-pro-max/models-cache.json`), refreshed on demand; it is **not** a
  gate — local endpoints whose models are absent from the catalog keep working
  exactly as before.
- **Credential readiness, and a writable layer** — providers using `env_key`
  now show whether that variable actually resolves and from where: the launcher
  process environment (read-only), `~/.codex/.env` (writable here), or the
  project `.env` (read-only). A provider whose variable is missing is badged,
  and the active provider gets an inline warning instead of failing silently at
  request time.
- **Test connection** — each provider can be probed against
  `GET {base_url}/models` with the headers, query params and auth the real
  request would use. The result reports the endpoint, HTTP status and model
  count, or the concrete failure. Network failures and 401s are normal results
  here, not error toasts.
- **Import providers from other tools** — scans this machine for provider
  declarations (Codex's own config, Claude Code, opencode, and common
  `*_API_KEY` conventions) and imports the selected ones. Only **environment
  variable references** are imported; sources holding literal keys are counted
  and reported but never read. Existing routes are skipped rather than
  overwritten.
- **Guard toggles moved onto the Switch primitive** — the per-parameter
  applied toggle was a hand-styled `<input type="checkbox">` with a bespoke
  `.text-switch` recipe (now deleted). It is a real switch, matching the
  boolean field editor next to it.
- **Dialogs cap their height and scroll** — long dialogs previously grew past
  the viewport, putting their action buttons out of reach at small window
  sizes. Affects every dialog, not just the model screen.

## Verification

  removed `dsh` section and had **no model coverage at all**; it now drives the
  model screen end to end (22 new checks): active model and provider rows,
  catalog metadata, the model picker, the full provider editor with its
  round-tripped headers and unknown keys, the connectivity probe, the import
  dialog, and the `⋯` menu. The no-console-errors assertion still passes.

  (30 component + 28 pure-function tests new for the model domain).
- `pnpm exec tsc --noEmit` and `pnpm build` — clean.

- `node scripts/check-release.mjs --tag v1.23.0` passes.

## Upgrade notes

- **No migration needed.** `~/.codex/config.toml` is untouched until you press
  a write action, and every write is backed up to `~/.codex/dashi-backups/`
  first. Existing providers load with their extra keys intact.
- **Reasoning levels**: if a provider/model combination declared a level the old
  build would have rejected, it is now accepted and left as-is.
- **Stored provider API keys are never sent to the UI.** Opening a provider for
  editing shows an empty key field meaning “keep the stored key”; clearing the
  field explicitly and saving removes the key. Previously the plaintext value
  travelled to the frontend and back on every save.
- The first catalog load is an explicit **Refresh catalog** click (~27 MB,
  gzipped in transit). Skipping it changes nothing else on the screen.
- The guard's applied toggle renders as a switch now; its accessible name and
  disabled state are unchanged.
