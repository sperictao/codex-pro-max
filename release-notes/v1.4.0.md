# v1.4.0

功能版：DeepSeek Harness 远程访问切换为可授权的 Connection 插件架构，移除 Launcher 自建的 3898 回环反代，远程身份由 Tailscale Serve 提供并在 dsh 入口完成认证和授权。

## Features

- **完整替代内置 Connection**：固定集成 `dsh-client-connection-authz`（`873c465f1403`）和 `dsh-auth-tailscale`（`ea7ca9fa3db4`）。插件补丁按 `id + package name` 精确禁用内置 `@deepseek-ai/dsh-client-connection`，再注入带授权 Interface 的完整替代实现；Launcher 将兼容栈锁定为 dsh `0.1.0-rc.6`
- **Tailscale 身份授权**：从 `tailscale status --json` 精确解析当前登录身份，通过 `DSH_TAILSCALE_ALLOWED_LOGINS` 配置允许列表；HTTP、RPC 与 WebSocket 共用同一授权入口。远程普通调用按身份放行，远程特权 API 默认拒绝，本机真实 loopback 仍保留特权访问
- **直接 Serve 到 dsh**：链路简化为 `Tailscale Serve → 127.0.0.1:3899`，不再监听 3898，不再改写 `Host` / `Origin`，也不再伪造 `SSH_CONNECTION`；dsh 显式绑定 `127.0.0.1` 并仅信任当前 Tailnet FQDN
- **离线可安装的固定插件包**：两个公开仓库作为固定 commit 的 Git submodule 接入，构建阶段生成可复现 tarball 并打入 Tauri resources。运行时通过 `dsh plugin --profile web add` 幂等安装，无需访问 GitHub 或使用 Git

## Changes

- 远程访问检测、修复、启动和开机自启统一检查 dsh 核心版本与两个插件；状态卡新增插件安装步骤，并用“修复兼容栈”替代无约束升级
- 开机自启只管理 dsh web 服务；升级时清理旧 proxy supervisor、`start-proxy.*` 与遗留进程，但不会删除用户自己的 `~/.dsh/loopback-proxy.js`
- CI、Tauri 打包资源、双语文案、smoke fixture、README 与远程访问故障排查文档同步更新
